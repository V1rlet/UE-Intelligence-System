# GraphBrain 工程编码标准 v1

- `standard_id`: `graphbrain-engineering-standard`
- `format_version`: 1
- `status`: active
- `effective_date`: 2026-08-13
- `owner`: GraphBrain maintainers
- `exception_registry`: `config/engineering-standard-exceptions.json`

本标准把仓库 `AGENTS.md` 的工程宪法转化为日常编码、评审和验收要求。宪法优先于本标准；本标准可以增加约束，不得削弱宪法。`必须/禁止` 是合并前要求，`应该` 需要在评审中说明偏离原因，`可以` 是允许但不强制的做法。

## 1. 适用范围与变更协议

本标准适用于 `adapters/`、`core/`、`server/`、`viewer/`、`scripts/`、`tools/`、`tests/` 和根级 TypeScript 配置。生成的不可变数据、release 产物和归档证据遵循各自 Schema/manifest，不用代码风格工具改写。

规则使用稳定 ID。规则语义发生破坏性变化时必须提升本文件 `format_version`，提供旧例外登记的迁移或明确废止诊断，并同步 `AGENTS.md`、门禁与测试。不得在不改版本和测试的情况下改变规则含义。

## 2. 架构与依赖

### ARCH-001：依赖必须指向稳定能力边界

`core/` 不得运行时依赖具体 Adapter 实现，只能依赖精确的 `adapters/adapter-interface`、`adapters/diff-lib` 和 `adapters/registry` 边界。文件同名不构成能力声明。Viewer、Server 和工具通过领域服务、Schema、resolver 或协议协作，不直接读取彼此内部状态。

### ARCH-002：事实与派生状态分离

稳定 ID、关系、身份和发布状态只由 canonical owner 持有。筛选结果、坐标、缓存、加载状态和局部选择都是可丢弃派生状态；不得写回成为第二份事实。跨模块需要新事实时，先定义 owner、Schema、迁移和替换路径。

### ARCH-003：兼容逻辑只能存在于命名边界

旧 URL、旧格式、旧 API 和旧字段只能由版本化迁移器、route normalizer 或 retired adapter 处理。业务组件看到的必须是当前模型。新增兼容分支必须说明移除条件并有旧 fixture。

## 3. TypeScript 与数据边界

### TYPE-001：严格类型，不使用静默逃生舱

生产、工具和测试代码都不得使用显式 `any`。不可信或类型未知的输入先声明为 `unknown`，在 HTTP、JSON、文件、浏览器消息或进程参数边界缩窄。泛型应把调用者期望的返回类型显式带到边界，不能用 `any` 抹掉验证责任。

### TYPE-002：禁止未登记的类型压制

不得直接加入 TypeScript suppression 指令。确有第三方声明阻塞时，优先建立最小本地适配器或类型守卫；仍无法处理时，必须登记限时例外。类型断言只能发生在已经验证的边界，不能代替运行时校验。

### TYPE-003：公共契约必须可读且可验证

导出的领域函数、持久化模型、HTTP 输入输出和跨工作区状态必须有明确类型。联合状态应使用判别字段表达，不用多个可空字段制造非法组合。单位、软范围、硬边界和 ID 空间在类型或相邻常量中只有一个定义。

### BOUNDARY-001：外部输入 fail closed

所有文件、JSON、URL、HTTP body/header、环境变量和浏览器存储都视为不可信。边界必须限制大小和枚举、拒绝歧义、验证路径仍在允许根目录内，并把未知版本作为诊断而非猜测默认值。验证后的内部模型不重复散落防御性猜测。

## 4. 异步、资源与错误

### ASYNC-001：异步结果必须有所有权

可能重叠的请求必须使用 `AbortController`、`LatestRequestGate` 或同等的单一请求身份，拒绝旧完成覆盖新状态。组件卸载、source/scope 改变和任务被替换时必须取消或退休旧工作。加载、空、部分、错误和成功状态不得用同一个布尔值含混表达。

### ASYNC-002：资源创建者负责释放

事件监听器、计时器、WebSocket、图实例、对象 URL、文件锁、子进程和临时目录必须在同一所有权边界清理。清理应幂等；长生命周期改动必须通过 soak 检查 DOM、监听器和堆趋势。

### ERROR-001：错误分层且稳定

边界错误使用稳定状态码/错误码和面向用户的可行动说明；内部异常保留 cause 或日志上下文，但不得向 HTTP/UI 泄漏路径、堆栈或秘密。不得吞掉异常后伪造成功，也不得把取消、冲突、校验失败和服务器故障混成同一错误。

### SECURITY-001：权限与路径采用拒绝优先

写 API 必须执行既有 Origin/local marker/revision 保护；路径必须经过真实路径与允许根校验，不能依赖字符串前缀。密钥、源码正文、查询、用户标识和绝对工程路径不得进入非必要遥测。破坏性文件操作必须先解析并核对精确目标。

## 5. UI 与交互

### UI-001：语义、键盘和焦点是功能契约

交互元素使用原生语义或完整 ARIA 契约，必须有可访问名称、键盘路径、可见焦点和关闭后的焦点恢复。Modal/菜单/树/listbox/tab 使用共享导航与焦点工具，不在各页面复制一套键盘逻辑。颜色不能是唯一状态信号。

### UI-002：连续数值使用双输入

每个连续可调数值同时提供滑条和可键入、可校验的数字框。滑条可使用常用软范围，数字框必须允许模型硬边界内的精确值；二者共享同一个 canonical value、单位、边界和错误状态。

### UI-003：响应式与性能必须可测

新增工作区至少验证桌面、430px 移动端和项目 DPI 矩阵，无横向溢出、遮挡和不可触达控制。重型依赖延迟加载；根总览不得为了装饰预载完整事实图。Reduced motion、故障恢复和资源预算属于 release 契约。

## 6. 测试、变更和发布

### TEST-001：按风险选择最低验证集

| 改动类型 | 合并前最低门禁 |
| --- | --- |
| 普通 TypeScript、规范或局部 UI 逻辑 | `npm run check:fast` |
| Schema、迁移、Evidence、reading-context、publication | 上项 + `npm run check:data`；旧 fixture、幂等、保存/重载、冲突和回滚必须覆盖 |
| Viewer、Server、runtime 或 release 产物 | `npm run check:release`，浏览器 smoke 不得跳过 |
| 订阅、计时器、缓存、图实例或工作区挂卸载 | 上述相关门禁 + `npm run check:lifecycle` |

测试应验证可观察契约和失败路径；不要只复制实现。修复缺陷必须加入在修复前会失败的回归用例。跳过、未运行和环境阻塞必须如实报告，不能记为通过。

### CHANGE-001：保持最小且完整的变更面

不做与目标无关的大规模格式化、重命名或依赖升级。交付必须同时包含兼容、测试、文档和旧入口清理；不得为了缩小 diff 留下第二套系统。工作树已有改动默认属于用户，不能用 reset/checkout 覆盖。

### RELEASE-001：构建、候选和激活是三个状态

本地门禁通过只证明源码候选，不代表已部署。`service:prepare` 生成并验收不可变 release；`service:activate` 是需要明确授权的独立生产状态切换；激活后必须针对真实生产地址复验并保留 previous release 回滚目标。

## 7. 例外机制

### EXCEPTION-001：例外必须集中、精确、限时

唯一例外入口是 `config/engineering-standard-exceptions.json`。每条记录必须包含稳定 `id`、`rule`、仓库相对 `path`、精确 `line`、`owner`、具体 `reason`、可追踪 `tracking_issue`、`approved_on` 和 `expires_on`。

- 路径不得绝对化或包含 `..`，且必须指向现存文件。
- 例外只豁免同一规则、文件和行的一处实际违规。
- 过期、重复、未知规则、没有实际违规的陈旧例外或宽泛路径都会使门禁失败。
- 修复违规时必须同时删除例外；延期需要重新评审并更新到期日。

当前 v1 基线为零例外。新增规则应先修复基线；只有无法在当前交付中安全处理的外部阻塞才允许登记。

## 8. 评审清单

合并前确认：事实 owner 是否唯一；旧内容与退出路径是否明确；边界是否解析 `unknown`；异步结果是否会过期；资源是否释放；错误是否稳定且不泄漏；UI 是否键盘/移动可用；测试集是否匹配风险；旧入口和临时代码是否清理；是否需要且正确登记例外；构建、候选和激活状态是否被准确表述。
