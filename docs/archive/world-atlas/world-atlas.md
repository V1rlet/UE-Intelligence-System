# 关卡·体验编排：世界地图与玩家流程

世界地图把关卡、世界观与任务资料放到同一空间中查看，但不会复制这些资料。原方案继续
维护自己的内容；地图只保存稳定引用 `GraphRef`、地图几何、体验内容 `WorldBeat` 和明确写下的世界状态。

## 数据位置

每个项目位于 `data/world-projects/<project_id>/`：

- `project.json`：项目身份、地图文件、默认阶段以及参与组合的方案文件。
- `world-atlas.json`：空间、路线、体验内容与阶段快照。

`GraphRef` 采用 `{ domain, subsystem, node_id }`，运行时稳定键为
`domain/subsystem::node_id`。项目清单负责把多个不同 subsystem 组装到同一世界，Atlas
不再继承旧 `world_anchor` 的“必须同 subsystem”限制。

项目级关系视图通过 `project.json.views` 显式注册。服务端按 `domain`、`subsystem` 和
`revision_policy` 解析实际文件并返回 `resolved_views`；前端不匹配日期文件名，也不硬编码路径。

## 体验内容

`WorldBeat` 回答“某个阶段在某处发生什么”。它可以同时引用任务、目标、故事事件、人物、地点、
关卡节点与奖励，并带有出现条件和完成后的世界变化。二元跨域链接仍用于表达同一实体或实现
关系；需要地点、阶段与多个参与对象时应使用 Beat。

## 世界状态

条件是可校验的声明式 AST，支持章节范围、任务状态、Flag、all/any/not 组合。Atlas 只模拟
设计快照，不宣称等同于 UE 运行时存档。`core/world-atlas/evaluator.ts` 对同一数据执行确定性投影，
供 UI、测试、审计和后续 UE 导出复用。

## 3D 高程与路线

进入“关卡·体验编排”，或在制作工作台点击对应的关卡体验草稿：

- WebGL 透视相机使用左键轨道旋转、右键平移和滚轮缩放；
- 地点 `elevation` 使用米制高程，允许负值表示地下层；路线连通端点只由 `from/to` 的稳定
  空间 ID 决定，`via` 只保存 `[x, y, elevation]` 中间控制点，不能覆盖或漂移端点；
- 1×/2×/4× 高差显示倍率只改变观察比例，不改写设计内容；
- 2D 与 3D 共用空间拓扑探针；悬停会压暗无关内容并显示内外归属、高度层、包含、邻域和直接
  连通，地点路线同时显示方向、目标和高差，并沿 canonical 3D 曲线播放流动粒子；
- 切换阶段观察任务、路线与世界状态变化；
- 切换主线、支线、叙事、人物、设定、路线和区域图层；
- 点击地点会打开地点详情，并显示对应的方案内容。

## 地图与方案同屏查看

地图与方案编辑器不再是两个互斥页面。探索页的“世界工具”从右侧打开：左侧保留 3D
空间，右侧显示世界状态、关卡/任务/故事方案或世界关系。分隔条可
拖动调宽，并把宽度保存在本机：

- 地图选点会聚焦被引用的方案节点；
- 图谱选择会按 `GraphRef` 反向定位地图空间和 Beat；
- 关卡、任务、叙事引用可在同一地点的标签栏中切换；
- 图谱节点拖动继续调用设计图原有的版本化保存接口；
- 新建节点、建立关系、属性编辑、删除和定稿复用原 DesignEditToolbar；
- 原图文件与深链保留兼容，但三个独立模块不再占据设计分区主导航。

## 探索内统一空间白盒

旧地点与地形语义已迁入探索界面的统一空间白盒，不再维护单独的“地形要素”编辑器。右侧 2D
平面与左侧 3D 世界持续同步，可通过 `3D 优先 / 双视图 / 2D 优先` 三档比例或分隔条调整可视面积。点状地点
继续保留 `feature`、影响半径、备注与原领域引用。

位置、尺寸、朝向、网格、高程与影响半径等连续数值均使用滑动条作为主操作，并保留不受 UI
常用软范围限制、但受模型硬边界校验的数字输入。保存统一 POST `replace_world_draft`，白盒
与旧地点在同一次 `base_version` 检查和原子写回中提交；旧单地点 API 仅作为薄兼容层保留。

## 功能分层

- **探索**：默认占满可用空间，只保留悬浮标题、轻量地点卡和流向预演。
- **世界工具**：按需打开，可切换“世界状态 / 地点方案 / 世界关系”。
- 项目切换、关联检查和交付入口收进标题旁的菜单；地图页面不再重复显示应用级标题栏。
- 世界工具打开时 3D 限制为 30fps 和较低像素比；白盒编辑仍与探索视图保持同屏和数据同步。

内嵌关系图由局部错误边界隔离；单个镜头失败不会再卸载整个 Atlas。

## 空间与玩家体验

关卡工具表达可行走的空间底板；玩家行动与故事信息不复制空间，而是在同一个画布中组织玩家可能经历的内容：

- `空间底板` 维护地点、地形、白盒组件、路线、高度与连通性；
- 玩家行动按发生地点组织目标、选择、限制、奖励、失败与恢复；
- 故事信息按发生地点组织铺垫、揭示、角色、选择、后果、设定与回收；
- 两类节点共用轨道、可能性分支、顺序、强度、流程与非顺序因果影响，不维护两套画布；
- 界面先解释“玩家理解什么 → 做什么 / 如何分岔 → 世界产生什么后果”；工具栏、空状态、快捷键 `N` 与底部 `＋` 共用同一套 `理解 / 行动 / 后果` 类型选择器和领域工厂，不再维护两条建点逻辑；
- `Q` 表示玩家行动，`N` 表示玩家理解；主画布节点只显示类型、标题、顺序和关系状态，整个节点可拖放，右侧两个端口分别创建流程与非顺序影响；
- 内容的完整说明集中在右侧详情栏，按“核心体验 / 空间与组织 / 可能性连接 / 条件与世界变化 / 关联的设计内容”分区，避免主图与详情栏重复展示同一信息；
- `在哪里发生` 只表达地点、体验轨道 / 分支和节点落点，`如何推进` 负责自由编排流程与非顺序影响，两种视图消费同一组 Beat；
- 连线是可编辑关系：拖动节点到连线可把节点插入关系；`Alt + 左键` 点击任意连线会立即断开，键盘选中后也可按 Delete；“解除关系”只删除所选边，“解除附着”仅对单入单出节点恢复原关系，分支拓扑不会被自动猜测；
- 结构检查由同一连接解析器给出入口、出口、连通分量、关键路径、孤立节点、精确环与失效引用；2D、3D、Inspector、保存与撤销都消费同一组稳定节点/关系 ID；
- 两种雕刻层继续用 `participants` 引用原 Quest / Narrative / Level 图事实，工作台会展开显示这些事实的 `line`、`chain`、`unlock_mode`、`arc` 等结构属性；
- `when` 与 `effects` 仍是声明式条件树和效果列表，2D/3D 投影、阶段切换、保存和审计共用同一数据；
- 空间、地形、白盒与体验编排共用一套草稿快照撤销/重做；拖动空间对象或体验节点、建立流程与因果关系都可恢复。
- “保存项目”统一使用 `replace_world_draft`，在同一次 `base_version` 检查中完整写入 `data/world-projects/<project>/world-atlas.json`。体验内容位于 `atlas.beats[]`；`at` 是可选的发生地点，未选择地点时保持为空并给出提示，不会默认猜到首个地点；`transitions` / `influences` 保存明确建立的关系，`when` / `effects` 保存条件和世界变化。

当前格式为 v17。迁移会保留旧地点、条件、效果、关联内容与展示信息：v14 允许地点留空；
v15 使用共享交付信息；v16 允许分组、分支、顺序与强度留空，并要求旧值人工核对；v17
允许玩家行动在作者选择前保持“未分类”，既有主线、支线和故事分类原样保留。阶段、行为、
工作流、布局与选项集中声明在
`core/world-atlas/experience-carving.ts`，界面和服务端校验共同消费，避免在不同组件重复硬编码。
