# 产品定位

## 一句话

GraphBrain 是“已经实现的 UE C++ 代码架构”的只读浏览器，不是方案创作或生产管理平台。

## 用户问题

GraphBrain 回答：

- 这个系统由哪些模块、类型和函数构成？
- 类型之间有哪些继承、持有、调用、委托和模块依赖？
- 某个类/函数的真实签名和源码证据在哪里？
- 修改某个代码单元可能影响哪些已实现单元？
- 相比一份明确基线，哪些代码事实与关系发生了语义变化？
- 哪些人工代码标注因源码变化而陈旧？

GraphBrain 不回答并且不持久化：

- 游戏、架构、关卡、叙事或任务“应该怎么设计”；
- Programmer 应该实现哪些类或签名；
- 计划、复核、审批、交付、回执或进度状态；
- UE Level/Actor/Sequence 的空间与运行时事实。

## 所有权

| 信息 | 所有者 |
| --- | --- |
| 已实现 C++ 结构与关系 | GraphBrain `ue5_code` 提取图 |
| 对代码事实的人工观察 | GraphBrain annotations |
| 两个图快照的变化与一跳影响摘要 | GraphBrain versioned change report（派生、可重建） |
| 架构决策、实施方案、story、评审和交付 | ClaudeGameStudios |
| 空间、资产、Sequence 和运行时状态 | Unreal Engine / 项目资产 |
| 外部工具能力与状态 | ToolRegistry manifest / registry |

每个 2D、列表、详情、悬停、搜索和导出视图必须消费相同稳定 ID 的代码事实。布局坐标、选中状态、缓存和标注不得成为第二份代码事实。

## 可信度边界

- 图是源代码提取结果，不是对运行时行为的完整证明。
- 变化报告是两个提取快照的语义比较；一跳影响是关系推导，不等于必然运行时影响或待办。
- 标注是人工观察，不覆盖或改写提取事实。
- API 缓存可能落后于本机引擎源码，界面必须暴露来源与新鲜度。
- 归档数据不进入活动 catalog、API、校验或 UI。
