# GraphBrain UI/UX 全面审阅与重构方案

日期：2026-08-13（Asia/Shanghai）  
基线：GraphBrain 1.0.0，production release `release-b6f585f29dbd9de72b224dc24850b003e1febc24fc2076fabbe5da93ca0069a1`

## 1. 产品任务与审阅方法

GraphBrain 的首要任务不是“展示一张很大的图”，而是让使用者快速完成三个只读任务：确认当前证据是否可信；理解代码边界与关键关系；沿稳定 ID 下钻到源码证据。审阅覆盖总览、架构、关系、API、变化、Spec、帮助及 430px 移动布局，并以生产截图、DOM/键盘契约、资源预算和真实数据分布为依据。

持久化格式、Evidence API、URL 兼容和事实所有权不在本轮变更。UI 继续只消费 catalog preview、canonical graph resolver、change report 和 reading-context；任何分组、排序与坐标都只是可重建呈现状态。

## 2. 严重问题

| 优先级 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P0 | 架构根视图不可读 | 42 节点/29 关系被排成超长纵向森林，桌面初始缩放 12–13%，移动端节点几乎不可辨认 | 核心“理解边界”任务失败 |
| P0 | scope 会丢失跨组关系 | 选择 group 后只保留组内节点与组内边；例如项目类型到 UMG、Engine、CoreUObject 的关系消失 | 范围筛选改变了用户能看到的关系事实 |
| P1 | 总览行动层级重复 | Hero 的架构/API 入口、侧栏探索入口和唯一活动图卡片同时争夺注意力；单图状态仍展示筛选工具 | 首次进入时无法快速判断下一步 |
| P1 | 技术可信度与任务行动混排 | 文件名、状态、统计、预览和打开动作挤在同一大卡片内 | 可信度可见，但扫描成本高 |
| P1 | 架构命令栏在窄屏挤占首屏 | scope、模式、图例、返回和来源说明同时浮在画布之上 | 移动端有效画布进一步缩小 |
| P2 | 变化/API 页面信息密度偏高 | 技术标识与微型文字连续出现，重点依赖颜色和位置 | 长时阅读疲劳，但任务仍可完成 |

已有优势必须保留：总览/探索/变化三层信息架构明确；Evidence 状态贯穿；关系图和 Spec 下钻成熟；键盘焦点、深链、降级动效和移动安全区已有自动化门禁。

## 3. 重构决策

### R1：架构根视图从“全量缩放图”改为“事实范围总览”

根视图按 catalog preview 已有 `group` 字段生成范围卡片。每张卡只展示可证明的节点数、内部关系数、类型构成和关系种类，并直接进入该范围。根视图不创建虚构节点或关系，也不再渲染不可读的 12% 全图。

### R2：范围图保留一跳外部上下文

进入某个 group 后，主节点仍来自该 group；与主节点直接相连的其他 group 节点作为“外部上下文”显示，并采用弱化视觉。边仍来自原 preview，方向和类型不变。这样筛选只改变焦点，不删掉理解所需的直接关系。

### R3：断连组件采用确定性二维打包

保留无环主干与次级边语义，将多个断连组件按稳定排序打包到二维工作区，避免所有 root 堆在单列。坐标是纯呈现状态；相同输入得到相同位置。

### R4：总览改为“当前证据 → 主要行动 → 技术明细”

Hero 先回答“当前证据能否使用”，再给出浏览边界、查看关系和查询 API 的任务入口。只有多个活动条目时才显示目录筛选；单图状态不展示无意义筛选。目录卡降低预览高度，把状态解释与技术文件名分层。

### R5：命令与说明不遮挡内容

根总览使用普通文档流；范围图才使用画布命令栏。来源声明并入总览/范围上下文，不再悬浮覆盖节点。移动端优先保留 scope 与模式，次级操作图标化并维持 44px 触控目标。

## 4. 兼容与退出路径

- URL `view=architecture&scope=<id>` 保持；`root` 语义从不可读全图变为同一事实集的范围总览。
- group ID 仍由集中 `scopeIdForGroup` 归一化；未知旧 scope 回到 `root`，不猜测目标。
- catalog preview v1 是唯一输入；没有 preview 时显示明确诊断，不回退已归档参考图。
- GraphView、关系/API/Spec、Evidence/reading-context 协议不变，可单独回退本轮 React/CSS/布局函数而不迁移数据。
- 旧烟测断言随新任务模型更新；历史 URL、键盘与 production route 继续验证。

## 5. 验收指标

1. 架构根视图不挂载 Cytoscape，展示全部真实 group，总节点/关系与 catalog preview 一致。
2. 进入项目范围后同时看到项目节点和直接外部上下文，且没有合成 canonical edge。
3. 断连布局的纵横比受控；同输入重排后坐标完全一致。
4. 单活动图首页不显示目录搜索；证据状态和三条主要任务入口在首屏可见。
5. 430px、1366×768@125%、1920×1080@150% 无页面横向溢出或控件重叠。
6. 键盘 scope tree、深链、关系/Spec、变化证据和帮助焦点契约继续通过。
7. `check:fast`、build、bundle、9 组 browser smoke 全部通过且不跳过。

## 7. 后续迭代（不在本轮臆造实现）

- 基于本地聚合使用数据再决定是否缩减 favorites 快速入口和变化报告技术字段；当前数据不足以删除。
- 若需要更高层的子系统语义，必须由提取器/schema 提供稳定 capability，不能由 UI 根据类名前缀猜测。
- 若要保存个人布局，需另行设计显式版本化的 presentation profile；本轮布局保持可重建、无持久化。
